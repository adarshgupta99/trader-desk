STEP 0 (actuals) - nselib financial_results_for_equity discovery
Run 2026-10-08, against live NSE endpoints.
######################################################################

Function signature (from nselib source, capital_market_data.py):
  financial_results_for_equity(from_date=None, to_date=None, period=None,
                                fo_sec=False, fin_period='Quarterly')

This is NOT a per-symbol lookup. It queries NSE's
/api/corporates-financial-results feed for a DATE WINDOW across ALL
companies, then for every row it fetches that filing's individual XBRL
document (a separate HTTP request per row) and extracts a fixed list of
~60 XBRL tag names (see get_func.py's keys_to_extract) via the
in-bse-fin XBRL taxonomy namespace. Relevant fields for this spec:
  - BasicEarningsLossPerShareFromContinuingAndDiscontinuedOperations (EPS)
  - DilutedEarningsLossPerShareFromContinuingAndDiscontinuedOperations
  - RevenueFromOperations
  - NatureOfReportStandaloneConsolidated (standalone vs consolidated flag)
  - DescriptionOfPresentationCurrency, LevelOfRoundingUsedInFinancialStatements
    (units - confirms the lakhs/crores risk the spec flagged)

PROBLEM FOUND - this is a hard blocker, not a minor shape mismatch:

1. fo_sec=True (meant to filter to F&O securities) returned an EMPTY
   master list in every window tried: 1M, 6M, explicit 10-20 Jul 2026,
   explicit Jul 2026, Jan-Sep 2026. This parameter path appears broken
   or means something other than "F&O securities" in the live API.

2. fo_sec=False, pulled for a full trailing year (period='1Y'), returned
   only 87 rows across just 18 distinct symbols, ALL of them distressed/
   suspended smallcaps - not one mainstream large-cap:
   AHLWEST, AIFL, ARSHIYA, BALLARPUR, BHARATIDIL, BLUEBLENDS, CMICABLES,
   EROSMEDIA, GAYAPROJ, IL&FSTRANS, KANANIIND, LYKALABS, RMCL, SECURCRED,
   UNITEDTEA, VALUEIND, VIDEOIND, VSTTILLERS.
   Several of these (BALLARPUR, EROSMEDIA, VIDEOIND, ARSHIYA, IL&FSTRANS)
   are known NCLT/insolvency or long-suspended names. RELIANCE, TCS,
   HDFCBANK, INFY, WIPRO appeared in ZERO of the windows tried, despite
   all of them having reported real quarterly results in that span.

CONCLUSION: whatever NSE filing category this endpoint surfaces, it is
not the standard quarterly-results announcement every listed company
(including every F&O name) files every quarter. It looks like a narrow
"financial results" sub-category NSE requires from a specific class of
companies (possibly ones under extra disclosure requirements due to
suspension/insolvency), not the general results calendar. Using it as
the primary actuals source for watchlist F&O names, as section 6 of the
spec assumed, will not work - it would return nothing for essentially
every real watchlist symbol.

RECOMMENDATION (not yet actioned - needs Adarsh's decision): flip the
priority order in section 6 - make yfinance (get_earnings_dates()'s
reportedEPS column, confirmed populated in the original Step 0 run; or
quarterly_income_stmt) the PRIMARY actuals source, and drop nselib
financial_results_for_equity entirely rather than keeping it as a
"preferred, falls back to yfinance" path - there is nothing to fall
back FROM if it structurally never returns F&O names. Screener.in
scraping remains a possible secondary fallback if yfinance's own
coverage has gaps, same as the estimates side already plans for.
