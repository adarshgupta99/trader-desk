E2. CAVEATS on the above (added by inspection, not auto-generated)
======================================================================
- TCS's 2026-10-08 session shows only 6 bars (09:15..14:15 starts), missing
  a 7th bar. A full 375-minute session at 60-min bars with a START-labeled
  final short bar should be 09:15,10:15,11:15,12:15,13:15,14:15,15:15 (the
  last one 15 min, covering 15:15-15:30) = 7 bars. RELIANCE/HDFCBANK/INFY/
  WIPRO's reported *latest* timestamp is 15:15 (so they likely do have that
  7th bar), TCS's is 14:15. Script ran during a live session (9 Oct), so
  this is plausibly just "today's partial session" bleeding into what looked
  like "yesterday's" date boundary at fetch time, not a labeling bug - but
  it was NOT re-verified against a clean completed historical session. Must
  re-check against an old, fully-settled session before relying on "7 bars,
  last one short" as the final-bar rule.
- interval='1h', period='730d' returned 1073 *calendar* days of actual
  span (2023-10-31 to 2026-10-08), not 730. period='3y' then returned
  EMPTY for the same ticker with an explicit "range must be within the
  last 730 days" error. So the "730 days" cutoff is measured from *today*,
  not from the requested period length - period='730d' and period='3y' are
  both being clamped to [today-730d, today], and '730d' only "won" here
  because its naive start (today-730d) overlapped the allowed window while
  '3y''s naive start (today-3y) didn't. Conclusion: ~1070-1075 calendar
  days (~2.9 years) of real 1h depth is available per equity right now,
  consistently across all 5 names - comfortably enough for an 8-print
  cohort at quarterly cadence (8 quarters = ~2 years) for these large-cap
  names. Smaller/less liquid F&O names were not tested and may differ.
- get_earnings_dates() returns America/New_York-tz timestamps, not IST -
  confirms events_db.py's existing get_eps_history() already has to handle
  this (it does, via .date() before comparison), and any cross-reference
  against NSE's IST filing timestamp needs an explicit tz conversion, not
  a naive date compare on the raw index value.
