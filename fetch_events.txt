SPEC: F&O CORPORATE ACTIONS + EARNINGS DATES DATABASE
Repo: github.com/adarshgupta99/trader-desk (PUBLIC). Python / Streamlit on Streamlit Community Cloud.
Audience: Claude Code. The user is a coding beginner. Explain each command you ask him to run, in plain words.

======================================================================
1. GOAL
======================================================================
Track SCHEDULED corporate actions (dividends, splits, bonus, rights, etc.) and
earnings / board-meeting dates for NSE F&O-underlying stocks ONLY.
Store them in a persistent SQLite file (events.db). The Streamlit app reads it.
Scope is F&O stocks only. No other stocks.

======================================================================
2. DATA SOURCE
======================================================================
Package: nselib (pip install nselib). Add to requirements.txt. No API key, no auth.
Three calls, one call each. NO per-symbol loop.

  from nselib import capital_market
  capital_market.fno_equity_list()
  capital_market.corporate_actions_for_equity(from_date, to_date, fno_only=True)
  capital_market.event_calendar_for_equity(from_date, to_date, fno_only=True)

- Dates are strings in dd-mm-YYYY format (example: "05-10-2026").
- Forward window: today to today + 60 days.
- fno_equity_list() wraps NSE /api/underlying-information (symbol, name, lot size).
- corporate_actions_for_equity wraps NSE corporates-corporateactions (fo_sec=true).
- event_calendar_for_equity wraps NSE event-calendar (fo_sec=true): board meetings
  (results, dividend consideration, fundraise, etc.).

IMPORTANT - WHAT IS UNVERIFIED:
- Column names and field contents are UNVERIFIED. They come from reading nselib 2.5.1
  source code only. NSE returns 403 to datacenter IPs, so they were never seen live.
- The F&O stock count is unverified (roughly 180-210 historically). Print len().
- Do NOT assume column names. Discover them first (Step 1).

4. COLUMN MAPPING STRATEGY (FALLBACK / ROBUSTNESS)
======================================================================
- Normalize column names before use: strip, lowercase, remove spaces/underscores.
  Example: "Ex-Date" and "exDate" and "EX DATE" should all be findable.
- Write a helper pick(df, candidates) returning the first existing column from a

    symbol: symbol, sym
    purpose: purpose, subject, bm_desc, description, bmdesc
    event date: exdate, bm_date, date, meetingdate, eventdate

  dict, default=str). This allows re-parsing later without refetching.
- Parse dates defensively (try dd-MMM-YYYY, dd-mm-YYYY, YYYY-MM-DD). Store as
  ISO YYYY-MM-DD text. If a date cannot be parsed, skip that row, count it, and
  print the count. Do not crash on one bad row.

5. ARCHITECTURE
======================================================================
Files:
  scripts/fetch_events.py      the fetch + upsert job (new)
  scripts/discover_nse.py      discovery helper (new, Step 1)
  events_db.py                 small read helper used by the app (new, at repo
                               root next to data_loader.py; match existing style)
  events.db                    SQLite file (committed to repo by the job)

events.db is SEPARATE from market_cache.db. Cache wipes must never destroy it.
Do not touch market_cache.db or data_loader.py behaviour.

--- Schema (create with CREATE TABLE IF NOT EXISTS) ---
instruments(
  symbol      TEXT PRIMARY KEY,
  name        TEXT,
  lot_size    INTEGER,
  updated_at  TEXT          -- ISO timestamp UTC
)

events(
  symbol      TEXT NOT NULL,
  event_type  TEXT NOT NULL,   -- 'corp_action' or 'board_meeting'
  subtype     TEXT,            -- parsed from purpose, see below
  event_date  TEXT NOT NULL,   -- ISO date (ex-date for corp actions, meeting date for board meetings)
  record_date TEXT,            -- ISO date or NULL
  purpose     TEXT NOT NULL,   -- VERBATIM text from NSE, never edited
  source      TEXT,            -- e.g. 'nselib.corporate_actions' / 'nselib.event_calendar'
  fetched_at  TEXT,            -- ISO timestamp UTC of the fetch that last touched this row
  raw_json    TEXT,
  PRIMARY KEY (symbol, event_type, event_date, purpose)
)

Also create a small table:
meta(key TEXT PRIMARY KEY, value TEXT)
  Used for: 'last_success_at' (ISO UTC), 'last_error' (text or empty),
  'fno_count'.

--- Upsert ---
Use: INSERT INTO events (...) VALUES (...)
     ON CONFLICT(symbol, event_type, event_date, purpose) DO UPDATE SET
       subtype=excluded.subtype, record_date=excluded.record_date,
       source=excluded.source, fetched_at=excluded.fetched_at,
       raw_json=excluded.raw_json;
Same pattern for instruments (ON CONFLICT(symbol)).
Dates get revised by companies: a revised date arrives as a new row. Do NOT
delete old rows automatically in v1. Keep it simple.

--- Filtering ---
Insert event rows ONLY for symbols present in instruments (the fresh
fno_equity_list result). Count and print how many rows were dropped.

--- subtype parsing (dumb keyword matching, case-insensitive, on purpose text) ---
  contains "dividend"            -> 'dividend'
  contains "split" / "sub-division"/"subdivision" -> 'split'
  contains "bonus"               -> 'bonus'
  contains "rights"              -> 'rights'
  contains "result"              -> 'results'
  contains "buyback"/"buy back"  -> 'buyback'
  contains "fund raising"/"fundraising"/"qip"/"preferential" -> 'fundraise'
  contains "agm"/"annual general"-> 'agm'
  otherwise                      -> 'other'
Check "result" last among matches where a purpose lists multiple things; if a
purpose contains several keywords, pick the first match in the order above. Put the
list in one constant at the top of the file so the user can edit it.

--- fetch_events.py flow ---
  1. Compute today and today+60 days in dd-mm-YYYY (IST).
  2. fno_equity_list() -> upsert instruments (refresh only if the table is empty or
     older than 7 days; otherwise just load symbols from the table). Still fetch
     it if the table is empty.
  3. corporate_actions_for_equity(from, to, fno_only=True) -> normalize -> upsert.
  4. event_calendar_for_equity(from, to, fno_only=True) -> normalize -> upsert.
  5. On full success: set meta.last_success_at = now UTC, last_error = ''.
  6. Print a summary: instruments count, rows inserted/updated per source, rows
     dropped (non-F&O), rows skipped (bad dates).
Exit codes: 0 on success; non-zero on ANY failure (so GitHub Actions goes red
and the user notices). On failure, write meta.last_error but do NOT overwrite
last_success_at, and do NOT delete existing rows.

--- Politeness / retries ---
  - Only these 3 calls per run. No loops over symbols.
  - Retry each call up to 3 times with backoff (5s, 15s, 45s). Then fail.
  - Sleep 2 seconds between the calls.

6. SCHEDULING
======================================================================
Refresh daily at about 7pm IST (announcement-driven data; more often is pointless
and rude to NSE). Optional second run in the morning (about 8am IST).

Option A - GitHub Actions. Create .github/workflows/fetch_events.yml:
  - on: schedule cron '30 13 * * 1-5' (UTC = 7:00pm IST, weekdays) plus
    workflow_dispatch (manual button).
  - permissions: contents: write
  - steps: checkout, setup-python, pip install -r requirements.txt,
    python scripts/fetch_events.py, then commit and push events.db ONLY IF it
    changed (git diff --quiet events.db || commit+push). Use the default
    GITHUB_TOKEN. No custom secrets.
  - Optional morning run: second cron '30 2 * * 1-5' (8:00am IST).
  CAVEAT (state this to the user plainly): GitHub Actions runners are datacenter
  IPs and NSE blocks datacenter IPs. This workflow may fail with 403. That is
  expected to be possible, not a bug in the code. Test with workflow_dispatch once.

Option B - FALLBACK if Actions gets 403: a cron/launchd job on the user's Mac that
  runs scripts/run_and_push.sh:
    cd to the repo, activate the venv, python scripts/fetch_events.py,
    then if events.db changed: git add events.db, git commit -m "update events",
    git push.
  Provide a launchd plist (or crontab line) for 7pm IST daily, and explain how to
  install it step by step. Mac must be awake/online at that time; say so.

Do Option A first, test it. If it 403s, tell the user and build Option B.
Do not build both without checking.

The job commits events.db to the repo, so Streamlit Cloud picks up the new file on
redeploy/pull. Commit only when content changed (avoid noise commits). Keep
events.db small (a few MB at most); it only holds ~60 days forward.
